# Специфікація програмного забезпечення

## 1. Загальні відомості

| Параметр | Значення |
| Назва програмного забезпечення | ESP32 Hardware Wallet Firmware та PC Wallet Client |
| Призначення | Керування апаратним криптогаманцем, створення Ethereum-гаманця, перегляд адреси та балансу, підтвердження й підпис транзакцій |
| Апаратна платформа | ESP32 DevKit, LCD1602 I2C, rotary encoder, ATECC608 |
| Мережа для демонстрації | Ethereum Sepolia testnet |
| Канал зв’язку між пристроєм і ПК | USB Serial |
| Середовище розробки прошивки | PlatformIO, Arduino framework |
| Мова прошивки | C++ |
| Мова ПК-клієнта | Python |
| Версія програмного забезпечення | 1.2.0 |

Програмне забезпечення складається з двох частин: прошивки ESP32 та клієнтської програми для ПК. Прошивка відповідає за локальне керування апаратним гаманцем, генерацію й зберігання гаманця, взаємодію з LCD1602, енкодером та ATECC608, а також за підпис транзакцій після підтвердження користувачем. ПК-клієнт забезпечує взаємодію з мережею Ethereum Sepolia через RPC, отримання балансу, формування транзакцій та відправку підписаних транзакцій у мережу.


## 2. Мета програмного забезпечення

Метою програмного забезпечення є забезпечення роботи прототипу апаратного криптогаманця, у якому приватні дані гаманця створюються та використовуються на стороні апаратного пристрою, а ПК виконує роль транспортного й мережевого клієнта.

Основні задачі програмного забезпечення:

- створення нового Ethereum-гаманця на пристрої;
- генерація seed phrase за стандартом BIP39;
- отримання Ethereum-адреси за шляхом `m/44'/60'/0'/0/0`;
- відображення адреси, балансу та параметрів транзакції на LCD1602;
- підтвердження або відхилення транзакції за допомогою енкодера;
- підпис hash транзакції на ESP32;
- передача підпису в ПК-клієнт;
- відправка signed raw transaction у мережу Ethereum Sepolia;
- відображення результатів роботи в графічному інтерфейсі ПК-клієнта.

## 8. Вимоги до протоколу обміну

Обмін між ESP32 та ПК-клієнтом виконується через USB Serial у форматі JSON-рядків.

### 8.1 Запит адреси

```json
{"cmd":"address"}
```

Відповідь:

```json
{"type":"address","address":"0x3eeca0f1d3858be5152a08e957d371708fd42d74"}
```

### 8.2 Запит балансу

```json
{"cmd":"balance","address":"0x3eeca0f1d3858be5152a08e957d371708fd42d74"}
```

Відповідь ПК-клієнта:

```json
{"type":"balance","balance":"0.0500","symbol":"ETH"}
```

### 8.3 Запит підпису транзакції

```json
{
  "cmd":"sign_tx",
  "coin":"ETH",
  "amount":"0.001",
  "to":"0x68f6Dc5A351724926B372C96356646F6Ee29b85A",
  "fee":"0.00002282",
  "hash":"0xa99bce3eec0cbd2ce183f8f35269775ef5b4b4ebbea77da773669a8fbb56dfed"
}
```

Відповідь при успішному підписі:

```json
{
  "type":"tx_signature",
  "status":"signed",
  "r":"0x...",
  "s":"0x...",
  "recid":0
}
```

Відповідь при відхиленні:

```json
{"type":"tx_signature","status":"rejected"}
```

## 9. Вимоги до безпеки

| ID | Вимога | Опис |

| SEC-02 | Не передавати seed на ПК | Seed phrase та приватний ключ не повинні передаватися в ПК-клієнт |
| SEC-03 | Підтвердження на пристрої | Транзакція повинна підписуватися тільки після перегляду параметрів на LCD1602 |
| SEC-04 | PIN-захист | Підпис транзакції та перегляд seed phrase повинні вимагати PIN |
| SEC-05 | Відхилення транзакції | Користувач повинен мати можливість скасувати транзакцію до підпису |
| SEC-06 | Secure element | ATECC608 повинен використовуватися як апаратний елемент довіри та джерело додаткових даних для entropy |
| SEC-07 | Тестова мережа | Усі реальні перекази виконуються тільки в Ethereum Sepolia testnet |

## 10. Обмеження системи

| Обмеження | Опис |
| Тестова мережа | Прототип призначений для роботи з Ethereum Sepolia, а не з основною мережею Ethereum |
| ATECC608 | Secure element не підтримує secp256k1 для прямого Ethereum-підпису |
| LCD1602 | Через розмір 16x2 символи довгі адреси показуються частинами |
| ПК-клієнт | Для балансу та broadcast потрібне підключення до інтернету |
| RPC | Робота залежить від доступності Alchemy Sepolia RPC |
| Вхідні перекази | Виявлення вхідних транзакцій виконується через зміну балансу |
| Прототип | Пристрій не призначений для зберігання реальних коштів |

## 12. Висновок

Розроблене програмне забезпечення забезпечує повний цикл роботи прототипу апаратного криптогаманця: створення гаманця, відображення адреси, перевірку балансу, підтвердження транзакції на апаратному пристрої, підпис hash транзакції та відправку підписаної транзакції в Ethereum Sepolia. Програмна архітектура розділена на прошивку ESP32 та ПК-клієнт, що дозволяє відокремити критичні операції з приватними даними від мережевої взаємодії.
